# 新教會上線步驟

同一套程式碼可以部署給多間教會使用，每間教會有自己獨立的資料庫、照片儲存與網址，資料完全隔離。以下步驟約需 30 分鐘。

## 1. 建立 Supabase 專案（資料庫與照片儲存）

1. 到 <https://supabase.com> 登入，點「New project」。
2. 專案名稱用教會名稱，資料庫密碼請用產生器產生並妥善保存，區域選離教會最近的（台灣可選 Northeast Asia）。
3. 專案建立後，左側「Project Settings → Database」：
   - 複製「Connection string → URI」，選 **Transaction pooler**（port 6543），這就是 `DATABASE_URL`。把 `[YOUR-PASSWORD]` 換成剛才的密碼。
4. 左側「Storage」→「New bucket」：
   - 名稱 `member-files`
   - **取消勾選 Public bucket**（必須是私有）
   - 建立後不需設定任何 policy，本系統只用伺服器金鑰存取。
5. 左側「Project Settings → API」：
   - 複製 `Project URL` → `SUPABASE_URL`
   - 複製 `service_role` 金鑰 → `SUPABASE_SERVICE_ROLE_KEY`（此金鑰絕不可放到前端或公開）

## 2. 準備環境變數

複製 `.env.example` 為該教會專用的設定，逐項填寫：

| 變數 | 說明 |
|---|---|
| `CHURCH_SLUG` | 教會代碼，小寫英文與連字號，例如 `grace-church`。上線後不可更改。 |
| `NEXT_PUBLIC_CHURCH_NAME` | 教會名稱，會顯示在標題與登入頁。 |
| `NEXT_PUBLIC_CHURCH_ACCENT` | 介面主色，例如 `#2563eb`。 |
| `NEXT_PUBLIC_APP_URL` | 正式網址，例如 `https://directory.grace-church.org`。Passkey 綁定此網域。 |
| `DATABASE_URL` | 步驟 1 的連線字串。 |
| `BETTER_AUTH_SECRET` | 執行 `openssl rand -base64 32` 產生，每間教會不同。 |
| `STORAGE_DRIVER` | 填 `supabase`。 |
| `SUPABASE_URL` / `SUPABASE_SERVICE_ROLE_KEY` / `SUPABASE_STORAGE_BUCKET` | 步驟 1 的值。 |
| `SEED_ADMIN_EMAIL` / `SEED_ADMIN_PASSWORD` / `SEED_ADMIN_NAME` | 第一位管理員，只在初始化時使用。 |

## 3. 建立資料表與第一位管理員

在自己的電腦上，把上述變數放進專案根目錄的 `.env`，執行：

```bash
npm install
npm run db:migrate   # 建立所有資料表
npm run db:seed      # 建立教會與第一位管理員
```

看到「已建立管理員」即完成。之後可以把 `.env` 中的 `SEED_ADMIN_PASSWORD` 刪掉。

## 4. 部署網站

以 Vercel 為例（Cloudflare Pages、Netlify 等做法類似）：

1. 到 <https://vercel.com> 用 GitHub 登入，「Add New → Project」，選擇本程式庫。
2. 在「Environment Variables」貼上步驟 2 的所有變數（`SEED_*` 可省略）。
3. 按 Deploy。完成後把 Vercel 給的網址設為 `NEXT_PUBLIC_APP_URL`，或在 Vercel 綁定教會自己的網域後再更新此變數並重新部署。

> 注意：`NEXT_PUBLIC_APP_URL` 一旦有使用者建立 Passkey，就不要再更改網域，否則既有 Passkey 會失效，需要重新建立。

## 5. 上線後的第一件事

1. 用管理員帳號登入，到「我的帳號」更改密碼，並建立 Passkey。
2. 到「使用者管理」為同工建立帳號，指派角色。
3. 若使用 Supabase 免費方案：到 GitHub 專案 Settings → Secrets and variables → Actions → Variables，新增 `APP_URL` 為正式網址，啟用「Keep alive」排程避免專案被暫停。

## 6. 定期備份（強烈建議）

- **Pro 方案**：Supabase 每日自動備份，保留 7 天。
- **免費方案**：在 Supabase 的「Database → Backups」沒有自動備份。請每月至少一次在本機執行：

  ```bash
  pg_dump "$DATABASE_URL" --no-owner --format=custom --file=backup-$(date +%F).dump
  ```

  並把 `member-files` bucket 的照片用 Supabase 控制台下載保存。備份檔含會友個資，請加密保存在教會自己的雲端硬碟。

## 給第二間教會使用時

重複上述步驟即可：另開一個 Supabase 專案、另一組環境變數、另一個 Vercel 專案（同一個 GitHub 程式庫可以連到多個 Vercel 專案）。程式更新時，兩個 Vercel 專案都會自動重新部署。
